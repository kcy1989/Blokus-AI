# plan10:單學習者 RL 訓練手冊(runbook)

> 取代舊版「四學習者同桌同步更新」。舊版已放棄,原因見 §9。
> 使用方式:填 §1 參數表,對 AI 說「依 plan10.md 執行,參數如下」,AI 依 §3 逐步執行。

## 0. 原則(AI 不得自行增減)

- 一次只更新 **1 個**學習者,其餘對手**全部凍結**。
- 事實、推測、建議分開標示;無證據不下結論。
- 判準與停止規則**跑前寫入證據 README 並提交,跑後不改**。
- 唯讀回報 → 等裁示 → 執行。不推送。各步獨立提交。
- 範圍外的碼改動(含 §2 前置)先停下問。
- 不得寫入或覆寫任何既有訓練目錄與 `ai/checkpoints/` 內既有席位。

## 1. 參數表(使用者只填這裡)

| 參數         | 說明                              | 範例                                                                                               |
| ------------ | --------------------------------- | -------------------------------------------------------------------------------------------------- |
| **學習者**   | 風格底(h / i / b / o)及起點檢查點 | h1000_20k                                                                                          |
| **對手池**   | 席位清單,訓練期間凍結             | fox, chess, wolf, optimizer, builder, intruder, hunter, h1000_20k, i1000_20k, o1000_20k, b1000_20k |
| **目標局數** | 累計局數(含起點已有局數)          | 50k(起點 20k,新增 30,000 局)                                                                       |
| 評測判準類型 | 見 §5:`非劣效`(預設)或 `優於`     | 非劣效                                                                                             |
| 起點對照     | 評測時配對的參照                  | 學習者自己的起點(預設)                                                                             |

派生值(AI 計算並回報,不由使用者填):

- 新增局數 = 目標局數 − 起點局數。
- 輪數 = 新增局數 ÷ 500。
- 每輪 500 局,學習者座位均勻輪換,每局從對手池**有放回抽 3 個**。

### 池的有效性檢查(AI 在 §3 步驟 1 回報)

1. 池中每個非人格席位,必須有「**預先註冊的評測結果**」支持其「已驗證」。AI 列出每席的證據出處,沒有就標「未驗證」,由使用者決定是否仍納入。
2. 池中是否含學習者自己的起點。若有,報告須標明「含自我對戰」。
3. 池是否含學習者的**下游版本**(例如訓練 h20k→50k 時池內有 h50k),不得有。

## 2. 一次性前置:自訂對手池支援

現況(待 agent 確認):`rl_train` 的 `rollout.make_specs` 僅支援七人格池。若不支援自訂池,列出最小改碼清單(區分改碼與資料),**停下問使用者**,核准後才改。

要求:

- 預設池(七人格)的行為與種子逐位不變,並有回歸測試。
- 池以席位 key 清單傳入,全部經 registry 解析,未知 key 直接報錯。

## 3. 執行步驟

### 步驟 1:唯讀回報(不改碼、不訓練)

AI 回報並停下等裁示:

1. 參數表與派生值(新增局數、輪數、預估時間,以實測每輪秒數推算)。
2. §1 的池有效性檢查三項。
3. §2 現況與需改碼清單。
4. 起點檢查點的路徑、sha256、`entropy_reference`、優化器狀態是否存在。
5. 續訓方式:
   - 若起點由本管線產生:`resume=True`,續輪號。
   - 若起點由其他管線產生:列出不相容項與對「同一條路」的影響。
6. 訓練種子段與評測種子段各一,先 `reject_reserved_seeds` 確認 FREE,互不重疊。
7. 輸出目錄與入池所需改動的檔案清單(區分改碼與資料)。

### 步驟 2:註冊與判準提交

1. 註冊種子段(訓練、評測各一列),獨立提交,全套測試與 `python -m ai --check` 綠。
2. 把 §5 判準與 §6 停止規則,連同參數表實值,寫入證據 README,提交。
3. 提交後才能開訓。

### 步驟 3:訓練

- 入口:`python -m rl.rl_train`,`n_procs=8`,每輪存檔。
- 起點、對手池、種子依步驟 1 裁示。
- 訓練期間**不得跑全套測試**,不得手動中斷或調整。
- 每輪記錄:rollout/update 秒數、entropy、guardrail 狀態。
- 訓練前後各驗一次**凍結席 sha256 不變**。

### 步驟 4:評測

1. 小批實測速度,再排程。
2. 新註冊 FREE 種子段,**1000 局**,argmax 與 softmax **各一**,配對起點對照。
3. 回報 `paired_diff`、`paired_se`、`|d|/se`,依 §5 給結論,**停下等裁示**。

### 步驟 5:入池(僅在 §5 通過後)

見 §7。

## 4. 訓練設定(固定,除非使用者另行裁示)

| 項目       | 值                                                                                                 |
| ---------- | -------------------------------------------------------------------------------------------------- |
| 學習者     | 1 個                                                                                               |
| 每輪局數   | 500                                                                                                |
| 對手       | 池內有放回抽 3 個,每輪局全部凍結                                                                   |
| 學習者座位 | 均勻                                                                                               |
| 單局獎勵   | `r = (5 − 排名) − 餘格/100`,平手共享較好名次                                                       |
| PPO        | 沿用 `rl_train` 預設(lr 3e-5 / 1e-3、clip 0.1、epochs 3、minibatch 512、kl_coef 0、entropy_coef 0) |
| 存檔       | 每輪                                                                                               |
| 回報統計量 | 僅記錄,不影響梯度                                                                                  |

## 5. 評測判準(預先寫死)

評測對象:訓練後的學習者 vs 起點對照。1000 局,argmax 與 softmax 各一,新註冊 FREE 種子段。

SE 約 0.0444(1000 局),2×SE 約 0.089,即**非劣效容忍度約 0.09**。

### 判準類型 A:非劣效(預設)

- 兩個模式**都**未證明落後(不滿足 `paired_diff < 0` 且 `|d| ≥ 2×paired_se`)→ 通過。
- 任一模式證明落後 → 不通過。
- 通過只代表「沒證明更差」,**不代表更強**。報告須明示。

### 判準類型 B:優於

- 兩個模式 `paired_diff > 0` 且 `≥ 2×paired_se` → 通過。
- 這個門檻很嚴:歷史上沒有任何檢查點被證明強於 20k。通過機率低,不通過本身有資訊。

### 通用

- 候選數固定為**一條**。不得因結果不佳再開第二條;重做是新決定,由使用者下並註明是在看過結果後做的。
- 只比起點對照,不與其他版本比。
- 多個學習者各自訓練時,每個各自套一次判準,**不得跨學習者挑選**。

## 6. 停止與 guardrail 規則(預先寫死)

- guardrail:`nan_or_inf`、`entropy`(`< 0.5 × entropy_reference`)、`first_ratio_dev`、`disk`。觸發 → 存檔後中止,exit 1。
- 任何非 `disk` 的觸發:訓練視為未完成,**不評測、不入池、不續跑、不調閾值、不開第二條**。結果照記為「第 k 輪被 `<name>` 中止」,附 entropy 軌跡。停下等裁示。
- `disk` 例外:清出空間後 `resume=True` 續跑,證據註明。
- 不設「達到目標局數前自動停止」以外的停止條件。中途 entropy 下滑也不得手動介入。
- `entropy_reference` 若沿用起點檔內的值,須在證據註明其來源環境,以免誤讀閾值。

## 7. 入池流程(僅通過 §5 後;每個學習者一個獨立任務)

1. 檢查點複製入 `ai/checkpoints/rl_{x}1000_{局數}/`,sha256 與來源相等後才進版控。`data/` 原件保持 gitignored,名冊 `source` 欄記其路徑。
2. `ai/registry.json` 末尾加一列;`seats.RL_SEATS` 加一列;`config.I` 加說明鍵。
3. 同步更新 `tests/test_registry_json.py`(白名單、列序、三元組)與 `tests/test_match_pool.py`(`GOLDEN_POOL`,GOLDEN 種子重採,附舊→新對照與命令)。
4. **訓練用的對手池不隨入池擴張**。要用新池,須在新一輪參數表明確寫出。
5. 全套測試、`python -m ai --check` 綠、`git status` 乾淨後回報 hash。
6. **不得覆蓋既有席位**:路徑、key、registry 列全部不同名。
7. 入池後新席位列為「待校準」。

## 8. 已知風險(須在報告中標明相關者)

1. **自我對戰**:池含學習者起點時,部分局是自我對戰,對外實力解讀要保守。
2. **對凍結池過擬合**:單向訓練,凍結對手不會反過來適應,學習者可能只學到這批對手的弱點。評測要用池外對手或新池補驗。
3. **對手池與部署分布不一致**:訓練時的池不等於實際遊戲池,softmax 與 argmax 表現可能背離。這就是 §5 要求兩模式都測的原因。
4. **argmax 不受訓練目標控制**:訓練優化的是 softmax 抽樣下的期望報酬,沒有項要求 top-1 可靠。argmax 表現是副產品,可能漂移。
5. **多重比較**:每多一個候選、多一輪查看,就增加假陽性。§5 的「一條候選」就是為此。
6. **事後選擇**:不得看過結果後改判準、改種子段或改池。
7. **種子守衛**:`own` 豁免比對完整三元組,新段註冊與 `rl_train._claimed_train_block` 的搜尋範圍必須一致,否則會被擋。
8. **entropy 基準錯配**:若起點來自不同環境,基準值與新池不一定相稱。
9. **機器間 float32 非確定性**:同一設定在不同機器可能有小數位差異,不是程式變動。
10. **凍結席與學習者不得共用權重物件**:前後以 sha256 檢查。

## 9. 歷史與放棄原因

- 20k→50k 由 plan10 舊版(四學習者同桌 + 固定 11 席池)完成,證據在 `eval/rl-multiple-train/`、`eval/rl-multiple-train-rb80/`。
- 結果:h 的 50k 在 argmax 下對 20k 有四份排程的負號證據,o 不穩,b、i 無落後;softmax 下持平。
- 放棄原因(機制,推測):
  1. **非平穩**:四個學習者同時更新,對手分布隨步而變。
  2. **歸因困難**:變化無法歸於某一因素。
  3. **循環與過擬合風險**:同桌共同演化可能學出彼此的剋制招。
- 注意:「3 個變差的以為自己變好」不是 PPO 的機制,因為優勢值來自自己的報酬,不來自對手的變化。
