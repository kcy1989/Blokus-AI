## 2. H1-0 必查項回報（只讀，先做）

`plan5.md` 要求讀完 `ai/` 的 optimizer 實作後回報這五點，再寫 v3。以下逐項附檔案與行號。

### 2.1 v1「可放空格選項數」的確切定義

**位置：`ai/optimizer.py:91`**

```python
scored = [(F.place_state(ctx["board"], n, oi, b, ctx)[4].bit_count(),
           n, oi, b)
          for _s, n, oi, b in cands[:OPTIMIZER_SCAN]]
```

`F.place_state` 定義在 `ai/formulas.py:456-466`，回傳第五項：

```python
return ctx["own"] | placed, empt_after, need, avoid, need & empt_after & ~avoid
```

其中 `need0 = own_reach(...).need = dilate_diag(own) & empt`、`avoid0 = dilate(own) & empt`。所以第五項是

> **落子後，空的、斜對角接觸我方任一棋子（含新落子）且不與我方任一棋子共邊的格子數。**

**這是「可放格子的數量」，不是「合法步的數量」。** 一次合法步會覆蓋其中數格，而同一局面下合法步數（平均 214）與可放格數不是同一個量級。

**驗證**：我用一個逐格重建的 oracle（只用 `board.grid` 與 `config.B`，完全不呼叫 `ai.formulas` 任何 helper）比對同一個局面：兩者都是 **6**。

**對誰、在什麼時機**：對 `ctx["owner"]`（即正在落子的那位），在**落子之後**的盤面上。

**與「我的可放選項」是否同一個量：是。** 所以不停下。

### 2.2 完整流程，以及「選項數」用在哪一步

| # | 位置 | 內容 |
| --- | --- | --- |

| 2 | `ai/chooser.py:206` | `cands.sort(key=lambda t: t[0], reverse=True)`，依**權重**分數降冪 |

### 2.3 同分時的打破規則

**沒有顯式的比較 key。** Python 的排序是穩定的，所以：

> 同分 → 維持 `restrict` 的輸出順序 → 依**權重**分數降冪 → 其順序是 `(手牌中的棋子順序, orientation 索引, base 升冪)`。

`_build_shortlist` 的 `best = scored[0][0]` 取的是排序後第一個，而 `shortlist[0]` 就是 `rescore` 的第一位，所以最終選中的是**排序後的第一個**。

v3 必須沿用同一條鏈，否則任何一個同分都會選到不同的棋。測試裡的 oracle 因此是「依 `restrict` 順序遍歷並保留**嚴格**最大值」，而不是對無序清單取 `max`——後者在任何一個同分上都會選錯。

### 2.4 計算「某玩家在假想局面下的選項數」的現成函式，以及對對手呼叫的已知問題

**現成函式**：`F.place_state(board, name, oi, base, ctx)[4].bit_count()`，其中 `ctx = F.board_context(board, hand_names, owner, must_cover)`（`ai/formulas.py:382-404`）。

對**對手**呼叫時，三個問題與處理：

**(a) 「對手沒有落子」時要給什麼定義。**
`board_context` 在 `own_reach` 為 `None`（該玩家尚未落子）時把 `need0`、`avoid0`、`legal_before` 全部設為 0，此時第五項就是 `dilate_diag(placed) & empt_after & ~dilate(placed)`，也就是「只算新落子那一塊斜對角的空格」。

這給出一個關鍵恆等式：**`placed = 0` 時，第五項恆等於 `legal_before`**。所以「對手的可放選項數」有了一個不需假想落子的定義：**v1 的表達式在虛落子處的值**，而這正是 `board_context` 已經算好的欄位。

選「虛落子」而不是「對手能下的最好一步」的理由：後者要在我的每個候選上再對對手的整個候選集做一次搜尋（約 94 個候選 × 對手候選集），量級完全不同；前者跨玩家可比、也夠便宜。測試以 oracle 釘住這個恆等式。

**(b) 增量式的正當性。**
`A_j*(後) = playable_before_j & ~placed`。`F.own_reach` 只讀 `board.owner_bits[owner]`，所以**我的棋子不會進入 j\* 的 need 或 avoid 集合**，對 j\* 的可放集只造成「少了幾格」。實測 **2010 組（對手 × 候選）全部相符，0 組不符**。

**(c) 效能。**
`F.board_context` 實測 **8.830 µs**，因為它還要算 `anchor_v = cells_to_vertices(anchor)`；而 v3 只需要 mask，`F.own_reach` 只要 **2.446 µs**。所以 v3 用 `own_reach`。

**另一個假設，已量測而非推定**：某位玩家若還沒有任何棋子（`own_reach` 回傳 `None`），mask 記為 0。實測 **320 個書本後決策中，這種情況出現 0 次**——被測者走到第 4 手時，其餘三席都已至少動過 3 次手，仍是 0 棋子表示從第 1 手起就被卡死。這是**假設，已量測**，不是保證。

## 3. H1-1：v3 的實作與測試

### 3.1 `A_j*(後)` 與 `j*` 的定義（寫在實作之前）

依 2.4 的結論：

```
A_me(後)   = F.place_state(ctx["board"], n, oi, b, ctx)[4].bit_count()   # 與 v1 逐位元相同
A_j*(後)   = (playable_before[j*] & ~placed).bit_count()                 # 2.4(b) 的恆等式
score(m)   = A_me(後) − A_j*(後)
```

`playable_before(o) = F.own_reach(board, o).need & ~avoid`。

`j*` 在**落子前**一次決定：三位對手中可放格數最大者，並列時取**行棋順序上最接近我之後的那位**（下一位優先）。三位皆為 0 時，`max` 自然取到同一規則的第一位，且 `0 & ~placed = 0`，差分項恆為 0 —— 計劃要求的情況不需要特例。

### 3.2 實作

`rl/v3.py`（298 行）：

- `V3Brain(OptimizerBrain)` —— **子類別**而非 wrapper 的理由：緊急規則、最大棋子限制、`key`、`mistake_rate = 0` 都用繼承取得，不複製。**`ai/optimizer.py` 未被修改，也未被 shadow。**
- `context()`：呼叫 `OptimizerBrain.context`（所以 `A_me` 用的是同一個 ctx），再加上 `v3_masks` 與 `v3_jstar`。
- `rescore()`：候選範圍是 v1 的（`restrict` 輸出再截 `OPTIMIZER_SCAN`），`A_me` 呼叫 **`F.place_state` 本身**而非重寫，所以與 v1 **逐位元相同是建構上的，不是測試同意的結果**。
- `v3_diff_weight`：差分項權重，存在 instance 上而非 module global，測試才能在不影響其他測試的情況下設成 0。
- `choose_v3`：與 `rl.opening.choose_v2` 共用同一個 `BookTracker`、同一個逐步種子推導、同一個候選過濾、同樣的放棄規則。

**`j*` 在落子前決定，是計劃指定的，而且是有代價的**：一個把領先位置交給第四位玩家的棋，仍舊是對「當時的領先者」計分。見第 6 節。

## 4. H1-2：成對對照

### 4.1 三臂設計

一個 pair = 一個配置 × 一個局種子，打**三局**：被測者分別為 v1、v2、v3。

- 每席的兩條隨機流由 `(game_seed, seat)` 推導（`rl/paired3.py:seat_seed`），**沒有任何參數表示被測者是哪一臂**。測試斷言 50 個種子 × 4 席 × 2 條流共 400 個值互不相同。
- **不使用隨機開局前綴** —— H0 需要它是因為書本的步是種子的確定函數；本階段 v2 與 v3 都照用書本，沒有可隨機化的東西。
- **成對固定的是對手的隨機性，不是對手的棋。** v2 與 v3 開局相同，但第 4 手起評分不同，盤面分岔，對手本來就該回答不同的局面；強迫盤面一致等於強迫對手下爛棋。

## 6. 異常與未預期發現

按重要性排列。

### 6.1 我在沒有授權的情況下跑了擴大

已在 1.1 完整說明。**判定以第一階段為準，擴大不參與判定。** 這一條列在異常之首，因為它是本報告唯一一個會影響可信度的程序問題。

### 6.2 B 組按座位的鏡像不對稱：席位 1 是 +0.4286、席位 2 是 −0.4212

兩個區間都不含 0（n 各 630，sd 約 1.26，標準誤約 0.05，所以 +0.4286 是 8.6 個標準誤），而這兩個值幾乎互為相反數。這不是雜訊。

**我沒有量到成因，所以不給結論。** 可以提出而**尚未驗證**的候選機制：並列規則用的是「行棋順序上最接近我之後的那位」，而 `CLOCKWISE_OWNERS = (1,2,0,3)`，所以被測者是席位 1 時優先序是 2, 0, 3，是席位 2 時是 0, 3, 1 —— **被測席位會改變誰被認為是「下一位」**，因此在計數並列時 j\* 的身分會隨席位系統性改變。B 組的三位對手中有兩位是規則式人格，它們的可放格數在對局早期經常並列。**這是推測，未經實測。**

這一項與 4.6 的次指標（B 組 `d31` 與 `d32_remaining` 皆顯著不利於 v3）方向一致，共同指向「**v3 對強對手的表現高度依賴席位**」，是下一階段該先查的東西。

### 6.3 對強對手，v3 的名次沒輸但餘格輸了

B 組主指標 `d32` 名次差 +0.0242（區間跨 0），但 `d32_remaining` 為 **+0.962**，區間 [+0.664, +1.2628] 不含 0。名次是 0.5 或 1.0 階梯的粗量，餘格是逐格的細量；v3 在 B 組的退化被名次平均掉了。依事先聲明不翻轉判定，但這是 4.6 中最值得記錄的一條。

### 6.4 42.8% 的 pair 三臂名次完全相同

`d32 = 0` 佔 0.428。差分項在 55% 的局面中改變了選步（3.4），卻在 42.8% 的對局中完全沒有改變最終名次。兩者不矛盾，但**「改了棋」與「改了勝負」之間有一道很寬的漏斗**，這是本階段效應量偏小的直接原因。

### 6.5 v2 與 v3 的名次相關係數只有 0.369，而它們前三手完全相同

見 5.1。一個只替換第 4 手起評分式的改變，把最終名次的相關性壓到 0.369。**這個改變比 H0 的整段開局替換還具有擾動性**（H0 的 v1/v2 相關是 0.206，但那兩者連開局都不同）。

### 6.6 `j*` 在落子前決定，是有代價的設計選擇

計劃指定 `j*` 在落子前決定，我照做了。代價：**一個把領先位置交給第四位玩家的棋，仍然是對「當時的領先者」計分。** 測試 2 找到並驗證了這樣的局面存在。這不是錯誤，是計劃指定的語意的必然結果，但下一階段若要改「每個候選各自選 j\*」，數字會變，不能與本階段直接比較。

### 6.7 對手沒有棋子的情況是假設，不是保證

`playable_before` 對尚未落子的對手記 0。實測 320 個書本後決策中出現 **0 次**，理由是被測者走到第 4 手時其餘三席都已至少動過 3 次。但這是**量測到的現況，不是結構性保證**；若未來有別的實驗讓某席從第 1 手起就被卡死並持續到第 4 手之後，該席的可放格數會被記成 0 而低估其潛力。

### 6.8 `OPTIMIZER_SCAN = 1200` 在 193 個書本後決策中一次也沒有綁到

候選數平均 94、最大 524。所以 v3 的候選範圍從未受上限裁切，H1 的數字不含「掃描上限截斷候選」這個混淆因素。

### 6.9 沒有異常的項目（如實列出）

- 書本在 7,500 個 pair 中從未被放棄，v2 與 v3 的書本行為在 50 局中 50 局一致。
- 第一階段獨立重跑與完整執行的前 3,000 個 pair 逐欄位相同。
- 1 進程與 4 進程逐位元相同。
- 每局的 `engine.stuck` 與 `Game.stuck` 一致（`play_game` 在任何一步不一致時會拋出，且兩向量都回傳供測試比對）。
- 名次與 `tools.benchmark.average_ranks` 一致（7 組測試案例，含全部並列的情況）。
