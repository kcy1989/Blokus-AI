#### B. 隨機性測量

母體：種子 0..99 的隨機對局，中盤（16 ≤ n < 48）決策點 3,200 個，
以種子 12,345 抽樣 500 個。量測時 `USE_WALL_BUDGET` 關閉，只讓 rng 成為變因。

| personality | mistake_rate（四座） | uses_lookahead | 進入加權抽籤 | 兩次選擇不同 | 佔比 | 抽籤後改變率 |
| --- | --- | --- | --- | --- | --- | --- |
| optimizer | 0.0000 ×4 | False | 0 / 500 | 0 / 500 | **0.0000** | n/a |
| wolf | 0.1205/0.1691/0.1270/0.1898 | True | 148 / 500 = 0.2960 | 122 / 500 | **0.2440** | 0.8243 |
| chess | 0.0402/0.0564/0.0423/0.0633 | True | 49 / 500 = 0.0980 | 37 / 500 | **0.0740** | 0.7551 |
| fox | 0.2009/0.2819/0.2116/0.3164 | True | 226 / 500 = 0.4520 | 183 / 500 | **0.3660** | 0.8097 |

**量測方法上的一個必要修正，如實說明**：隨機性完全來自
`chooser.py:268` 的 `rng.random() < brain.mistake_rate`，而流水線**每手只抽一次**
`rng.random()`。若照字面用兩個固定種子（1 與 2），
`random.Random(1).random()` 恆為 **0.134364**、`random.Random(2).random()` 恆為
**0.956034** —— 那是兩個固定數字，不是抽樣。我最初照字面跑，得到
chess 0/500 的結果，原因是 chess 的 mistake_rate（0.040～0.063）低於 0.134364，
**永遠不可能**通過那個判斷。改成每個局面從固定生成器
（`Random(12345 ^ 0x5EED)`）抽兩個種子之後，chess 才量到 0.0740。
這個修正只改量測方法，不改被量測的程式。

**top-1 模仿上限**（由高到低）：

- **optimizer：0% 隨機 → 確定性，模仿上限 100%**
- chess：7.40% → 上限約 92.6%
- wolf：24.40% → 上限約 75.6%
- fox：36.60% → 上限約 63.4%

比例的分解是乾淨的：`佔比 ≈ mistake_rate × 抽籤後改變率`。
以 wolf 為例，0.1488（四座平均）× 0.8243 = 0.1227，實測 122/500 = 0.122，
差異來自四座 mistake_rate 不等（0.1205～0.1898）。
「抽籤後改變率」不是 100%，因為加權抽籤有時仍抽回短名單第一名
（`PICK_TEMP = 5.0` 的 softmax 會讓第一名機率偏高）。

**對照組**：同一個 RNG 種子呼叫兩次，四個人格全部 0 / 500 = 0.0000。
差異不可能來自抽籤，所以零差異證明這條路徑在無干擾下是確定的。

### 終局評分規則（第 6 節 C）

**評分只用剩餘格數，沒有任何額外加分。** 沒有「全部用完加分」，
沒有「最後一塊為單格加分」，沒有輪到誰就用完誰贏的規則。

`game.py:188-189`：

```python
    def remaining_cells(self, owner):
        return sum(MASTER[n]["size"] for n in self.hands[owner].names)
```

`game.py:191-200`：

```python
    def standings(self):
        """(owner, remaining) for all four, best first.

        Remaining squares *are* the score: the fewer a player leaves on the
        board, the better they did. Ties are ordered by owner so the result is
        deterministic.
        """
        rows = [(o, self.remaining_cells(o)) for o in range(4)]
        rows.sort(key=lambda t: (t[1], t[0]))
        return rows
```

`engine.py:194-207` 的 `remaining_cells` / `result` 與 `Game` 同義
（改從 `hand_bits` 的 21-bit 整數算），200 局重播驗證兩者一致。

**並列的處理規則有兩套，行為不同：**

| 位置 | 規則 | 並列結果 |
| --- | --- | --- |
| `Game.standings`（`game.py:199`） | `sort(key=(餘格, owner))` | 並列者**依座位編號**排序，回傳整數序號 |
| `average_ranks`（`tools/benchmark.py:48-69`） | 競爭排名，並列者平分所跨名次 | 回傳**浮點平均名次**，`[5,5,9]` → `[1.5, 1.5, 3.0]` |

`Game.standings` 的並列以 owner id 決定先後，這是刻意的（deterministic），
但也是 D2 記錄過的座位偏差來源，所以評測工具不用它。
`standings()` 的呼叫點：`game.py:203,204`（`winner`）、`ui.py:674,694,1349,1350`。
`average_ranks` 的呼叫點：`tools/benchmark.py:48,161`、
`tests/test_benchmark.py:57,63,65,72`。

`winner()`（`game.py:202-207`）在並列時回 `"draw"`（若含玩家 0），
否則回最低 owner id 的字串。

另附：權重式人格的權重與 mistake_rate 每局乘 0.7～1.3 隨機擾動
（`ai/base.py:48-54`），所以上表的 mistake_rate 有四個不同值。
規則式人格（optimizer / intruder / builder）固定為 0，不擾動。

   `_legal_bases_for_orient`，差別在提前返回。

### wall budget 對可重現性的影響

同一個 RNG 種子呼叫兩次，但保留 `USE_WALL_BUDGET = True`（預設值，

## 異常與未預期發現

1. **情況 X 比我預期頻繁得多。** 我預期「延遲鎖存」是罕見邊界情況，
   實測是 **5.7% 的決策點、84% 的局**（168/200）。它正確但它很普通 ——
   架構上 `to_move` 就不保證該玩家能走。這對後續任何依賴
   `state.to_move` 可走性的程式都是必要前提。

2. **合法步數的峰值在中盤（16-23 手，825 個），不在開局。** 我預期開局
   候選最少（角格規則限制），實測開局平均 228、中盤 209 但 p95 與最大值
   都更高，峰值出現在棋盤攤開而尚未被圍死的 8-23 手區間。
   這對「候選數量隨進度」的模型容量規劃有意義。

3. **可落子棋子種類數最大值是 20，不是 21。** X5 永遠開不了局。
   這印證了 E2 的發現，但從另一個角度（不是「X5 開不了局」，
   而是「任何決策點最多 20 種棋子」）。

4. **`action_table.json` 不存逐 base 落點。** 30,433 這個數字在表內只有
   宣告欄位，`actions` 的 91 項是 `(piece, oi)` 而非落點。
   plan2 該項檢查因此只能做到「宣告值 vs 從 pieces.py 重算」，
   做不到「逐項比對表內容」。

5. **`choose_move` 不是純函式。** `USE_WALL_BUDGET`（預設開）讓它依賴
   掛鐘。本次量測中未觸發（最慢 16.4 ms ≪ 900 ms），但這是位置與負載的
   性質，不是位置與 rng 的性質。**任何「呼叫兩次比對」的重現性檢查
   都必須先關掉這個開關**，否則檢查的是機器負載不是程式。

6. **固定 RNG 種子量測隨機性會量錯。** 流水線每手只抽一次 `rng.random()`，
   所以「種子 1 vs 種子 2」實際上是「0.134364 vs 0.956034」兩個固定數字。
   chess 的 mistake_rate 0.040～0.063 低於 0.134364，照字面量會得到
   假的 0%。修正方法（每局面從固定生成器抽兩個種子）已在報告中說明。

7. **`builder` 的短名單 K 最大值 40 = 理論上界**，其餘五個人格是 34 或 37。
   角格保留（`CORNER_RESERVE = 6`）只在 builder 上偶爾被填滿。

8. **`to_plane` 的成本集中在 `normalize`（65%）**，且 `to_plane` 與
   `hand_vectors` 各自呼叫 `normalize`，同時呼叫兩者會重算旋轉。
   `normalize` 的旋轉是純 Python 逐格掃描 400 格。

四個開局合法步數相等（皆 58）且與暴力法一致、情況 Y 出現 0 次、
picked 轉換合法率 100%、引擎與 `Game` 終局餘格 200 局全一致、
情況 Y 未出現時所有局面都能終局。
