`data/hc2/`（皆已 gitignore）。

程式碼基準：**`51d26d7`**（plan7-A，「Latch stuck seats exactly」）。
`data/hc1/manifest.json` 記 `commit=51d26d7, dirty=false`，資料與訓練都能追回這一個 commit。

### 1.1 `stuck` 差在哪裡

| 項目 | 數值 |
| --- | --- |
| 有差異的列 | 190,349（15.97%） |
| 差異的「座位-回合」格 | 269,592 |

兩個結構性事實值得記下：

- **seat 0 從不差異。** 掃描從 owner 0 開始，短路只可能落在 0 之後，所以這個 bug

- **受測者自己的座位從不出錯。** 資料列只在行動者有合法步時才產生，所以真正餵進網絡
  的那一列，其 `stuck` 通道本來就是對的；受影響的是同一列裡**其他三席**的通道。
  這解釋了為什麼 plan7-A 的修正讓模型行為幾乎不變。

## 2. 訓練：`data/hc2`

設定與 H-B2 只差三項，其餘全部沿用（27 通道、batch 256、AdamW wd 1e-4、峰值 1e-3、
終點 1e-5、fp32、單一固定種子 20260903、64 通道 × 6 區塊）：

```
total_steps            50000 -> 10000
lr_schedule_end_step   50000 -> 10000
checkpoint_every        2000 ->  1000
```

warmup 維持 500 步。

### 2.1 LR 曲線對照

| 步數 | 舊 H-B2（50k 排程） | 新 H-C2（10k 排程） |
| --- | --- | --- |

兩條曲線在前 2,000 步幾乎重合；分岔主要發生在 2,000 步以後，10,000 步時相差 91 倍。

## 3. 評測

`match.py`，8 個選項 = 7 個人格 + 受測檢查點，argmax，全 `--dry`，`--out` 指向 `/tmp`，
每組 5,000 局。依 `plan7.md` 第 6 點，各組用不同種子。

| 檢查點 | 種子 | 席次 | 平均分 | 標準誤 | 平均餘格 |
| --- | --- | --- | --- | --- | --- |
| hc2 step_002000 | 910001 | 2,511 | 3.1250 | 0.0191 | 10.89 |
| hc2 step_005000 | 910002 | 2,568 | 3.0884 | 0.0189 | 10.92 |
| hc2 step_010000 | 910003 | 2,495 | 3.1287 | 0.0195 | 10.85 |
| hb2 step_002000（舊） | 910004 | 2,656 | 3.1570 | 0.0181 | 10.77 |

**四組全部落在 3.09–3.16，最大差 0.069，約 2.6 個合併標準誤。沒有任何一組與其他組
有可辨識的差距。** 同一局裡其餘七席的分數在四組之間也都落在 ±0.06 內
（例如 hunter 3.126 / 3.136 / 3.114 / 3.081）。

### 3.1 這個結論的界限

- 各組種子不同，所以「H-C2 vs H-B2」是**兩組獨立樣本**，不是配對比較。
  `match.py` 印的 `points_stderr` 是**組內**跨席的標準誤；跨組比較還要加上組間差異。
  上表的「合併標準誤」即為兩者合成。
- 2,500 席、標準誤 0.019，這個量級分辨得出約 0.06 的差距。要把 0.03–0.07 這種
  邊際差異講清楚，需要更多局或**配對種子**（同種子跑兩組）。
- 單一訓練種子、10,000 步。沒有重複實驗。

## 4. 結論

1. 修掉 latch 少報之後，`data/hc1` 的 `stuck` 欄位第一次與規則**零不符**，
   而資料的其餘 13 個欄位與 H-B1 逐位元相同 —— 這是一次乾淨的單變數實驗。
2. H-C2 在 10,000 步內驗證損失單調降到 0.9768，無過擬合，無發散。
3. **評測上三個 H-C2 檢查點與舊 H-B2 step_002000 無法區分。**

換句話說：**這個修正改變了資料與特徵的語意，但沒有付出可測得的強度代價。**
一個合理的部分是原因：受影響的通道描述的是**其他三席**，而模型輸出的是自己的著法，
這三個通道對當前決策屬於弱線索。

還不能宣稱的是「修正讓模仿更強」。要回答那個問題需要配對種子或更大的樣本，
不屬於本階段的量級。

## 5. 與 `plan7.md` 指示不符之處

1. **`--prefix hb1`**：`rl/caches.shard_order()` 寫死 `startswith("hb1_")`。若 `data/hc1`
   用 `hc1_` 前綴，`Resident` 讀不到資料。改用 `--prefix hb1` 讓檔名與 hb1 一致，
   資料集靠**目錄名**區分。未改共用程式碼。
2. **一併建了 `labels_view.npy`**：指示第 3 點只寫 `legalactions.npz`，但 `Trainer`
   使用的 `C.Resident` 同時需要 `labels_view.npy`，缺它訓練無法啟動。
3. **`rl.caches.build_legal_cache` / `build_label_cache` 無法使用**：兩者的 pool worker
   是閉包，而 `pool.map` 即使在 `fork` start method 下也要 pickle 函式物件，實測拋
   `AttributeError: Can't pickle local object ...<locals>.one`。改寫為模組層級 worker，
   並**先對 `data/hb1` 重建兩個快取做驗證**：`labels_view.npy` 相同，
   `legalactions.npz` 的 flat/offsets/counts/shards/rows 全部相同
   （240,569,093 索引），確認產物格式與 H-B2 訓練時所完全一致。
4. **評測用薄驅動呼叫 `match.main()`**：`match.py` 的 CLI 沒有 `--checkpoint-dir`
   （`run_league()` 有該參數，但 `main()` 沒往下傳），而 `step_5000` / `step_10000`
   也不在 `seats.IMITATION_STEPS` 內，`--pool` 會判為未知名稱。驅動程式只設定
   `seats.IMITATION_CHECKPOINT_DIR` 與 `seats.IMITATION_STEPS` 兩個 module 屬性；
   argparse、pool 展開、`--dry`、`summarise`、`--out` JSON 全部仍走原路徑。
   未為一次量測去修改共用程式碼。
5. **`tools/cross_check_engine.py` 未執行**：`plan7-B` 未要求，且 plan7-A 已驗過
   （115,138 步 IDENTICAL）。
6. **評測輸出全部寫入 `/tmp`**，`data/match/` 維持 3 檔未動。
7. **repo 程式碼零改動**：本階段只新增本檔與 `reports/hc2_raw.json`。
   全套 `-n 8` 仍 **764 passed**（262.6 s）。
8. **`data/` 檔案數 142 → 230**（`data/hc1` 75 檔、`data/hc2` 13 檔，其餘不變）。
