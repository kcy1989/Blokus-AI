## H1-1. `optimizer_v3`(`rl/v3.py`)

### 行為
1. 前 3 步:沿用 `rl.opening` 的書本邏輯(與 v2 完全相同,包含種子推導與放棄規則)。
2. 第 4 步起,或書本放棄後:
   - **落子前**對其他三位玩家各算一次「可放選項數」(沿用 v1 的定義),取最大者為強敵 j*。
   - 並列時,取**行棋順序上最接近我之後的那位**(下一位優先)。此規則固定,不得更改。
   - 若三位的選項數都為 0,則 j* 取同一規則的第一位,差分項恆為 0。
   - 對每個候選步 m(候選範圍與 v1 的 `restrict`/shortlist 一致,見 H1-0 第 2 點),在假想局面中計算 `A_我(後) − A_j*(後)`,取最大者。
   - `A_j*(後)` 以**真實座標的 State** 套用 m 後,對 j* 重新算(j* 的手牌不變,盤面包含我的新棋)。
   - 同分打破規則與 v1 相同。
3. 其餘(棋子大小限制、rescore 等)**保留 v1 的邏輯**,只替換最終用於排序的分數。具體替換位置依 H1-0 的回報,先寫在報告再實作。
4. v3 不修改 `ai/`,以包裝或子類別實作,放在 `rl/v3.py`。

### 測試(`tests/test_rl_v3.py`)
1. 分數公式用一個**獨立的** oracle 實作比對(不共用 v3 程式碼)。在 100 個真實局面上,v3 選出的步的分數 = 候選中最大分。
2. j* 在落子前選定:構造一個局面,使「落子後最強者」不同於「落子前最強者」,驗證 v3 仍以落子前的 j* 計分。
3. 並列規則:構造選項數並列的局面,驗證取到的是行棋順序最近的那位。
4. 退化檢查:若把差分項權重設為 0,v3 的選擇與 v1 在 100 個局面上逐項相同。
5. 差分項**不是常數**:在 100 個局面上統計,同一局面不同候選的 `A_j*(後)` 有變化的比例,回報。若為 0%,停下回報。
6. 書本階段:v3 前 3 步與 v2 在相同種子下逐項相同。
7. 確定性:同局面同種子重複呼叫結果相同。
8. `USE_WALL_BUDGET` 還原,包含例外路徑。
9. `rl/v3.py` 不 import `pygame`、`torch`。

### 診斷(只回報)
在書本之後的 500 個真實局面上:
- v3 與 v2(= v1 的第 4 步起)選擇不同步的比例。
- v3 每步平均耗時與 v1 的比值。
- 若耗時比 > 10 倍,回報並建議如何縮小候選,但**不要自行縮小定義**。

## H1-2. 成對對照(`rl/paired3.py`)

### 三臂設計
一個 pair = 一個配置 × 一個局種子,打**三局**:被測者分別為 v1、v2、v3,其餘三位的人格、座位、局種子與隨機流(沿用 H0 的 `seat_seed` 方法)完全相同。不使用隨機開局前綴。

### 兩組
| 組 | 對手 | 目的 |
|---|---|---|
| A | 從 builder、intruder、wolf、chess、fox 抽 3 個,座位輪換,循環均勻 | 主要判斷 |
| B | builder、intruder、optimizer v1(座位輪換) | 對強對手 |

- 第一階段:A 組 2,000 pairs、B 組 1,000 pairs。
- 種子從 `4_000_000` 起,**必須 assert 與以下不重疊**:0–199、20,240,101–20,336,965、1,000,000–1,001,999、2,000,000–2,000,199、H0 使用的 3,000,000–3,001,999、3,100,000–3,100,999、3,200,000–3,202,999、3,300,000–3,301,499。
- 12 進程並行,同種子逐位元相同。

### 預先設定的判定規則(看結果前固定)
令 `d32 = rank_v3 − rank_v2`(負值 = v3 較好)。**唯一的主比較是 v3 對 v2**(同開局,只有第 4 步起評分不同)。

- 主指標:A 組 `d32` 平均,以 pair 為單位自助法 10,000 次,95% 區間。
- **採用 v3 作為候選老師**,需同時成立:
  1. A 組 `d32` 區間上界 < 0。
  2. B 組 `d32` 區間下界 ≤ 0(對強對手沒有顯著更差)。
- 若第一階段 A 組區間包含 0,可擴大**一次**:A 5,000、B 2,500 pairs(新種子,合併),同規則再判。不得再擴。須註明擴大等於看兩次,聯合假陽性率約 9.75%。
- 結果三種:**採用 v3**、**維持 v2**、**(擴大後)無顯著差異,維持 v2**。無顯著差異時不採用 v3。

### 次指標(只報告,不參與判定)
- `d31 = rank_v3 − rank_v1`、`d21 = rank_v2 − rank_v1`(平均與區間,描述性,不做多重比較校正)。
- 餘格差 `remaining_v3 − remaining_v2` 等,同上。**事先聲明:餘格是次指標,不得用來翻轉判定。**
- 按被測座位、按對手人格分組的 `d32`(描述性)。
- 三臂名次相關係數。
- 書本放棄比例。

### 效能要求
自助法請用 numpy 向量化(H0 的純 Python 迴圈太慢)。新程式不需要重現 H0 的區間,但需用固定種子並測試同種子重跑相同。

### 測試(`tests/test_rl_paired3.py`,整檔 < 60 秒)
1. 同一 pair 重跑兩次,逐欄位相同。
2. 同一 pair 內三局的三位對手人格、座位完全相同。
3. 配置分配均勻(最大−最小 ≤ 1)。
4. 種子範圍檢查會拒絕每一個重疊範圍。
5. 1 進程與 4 進程結果逐位元相同。
6. 名次與 `tools.benchmark.average_ranks` 一致。
7. 每局最終 `engine` stuck 與 `Game` stuck 一致。
8. 判定函式的各分支以假區間釘住,含「上界恰等於 0 不算小於 0」。
