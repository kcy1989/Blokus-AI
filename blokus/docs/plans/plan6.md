### H-B2 前置(已完成)

**遮罩預計算(可行,已建):** `legal_mask_view` 是純 GPU 步之外的瓶頸。實測每批 256:`legal_mask_view` 152.12 ms,`featurize_batch` 23.58 ms,分片列→`engine.State` 3.37 ms,GPU 步 42.56 ms —— CPU 側佔整步 84.3%。

預先計算每列的合法動作索引並稀疏存儲,實測結果:

| 項目                                                   | 值                                                       |
| ------------------------------------------------------ | -------------------------------------------------------- |
| 總合法動作數                                           | 240,569,093(平均 201.9/列,最大 1,193)                    |
| 視角遮罩 popcount 是否等於 `n_legal`                   | 是(400 列抽樣,0 例不一致,比值 1.0)                       |
| 稀疏存儲大小                                           | 931.34 MiB(int32 flat 917.5 MiB + offsets + counts)      |
| 12 進程預計算耗時                                       | 80.79 秒(14,749 列/秒,0.0678 ms/列)                     |
| 訓練時由稀疏索引還原 36,400 維遮罩(每批 256)            | **1.92 ms**,比 `legal_mask_view` 快 **79.4 倍**          |
| 檔案位置                                                | `data/hb1/legalactions.npz`(新檔名,未覆蓋任何既有資料)   |

結論:稀疏方案**可行**。存儲 931.34 MiB 是原資料集 64.92 MiB 的 14.3 倍,但磁碟有 1.1 TiB 可用;預計算 80.79 秒屬資料前處理,不計入訓練時間。

還原遮罩後的每步時間(各項實測相加):CPU 側 3.37 + 23.58 + 1.92 = 28.87 ms,GPU 42.56 ms。

| 設定                       | 每步    | 50,000 步耗時 | 樣本/秒 |
| -------------------------- | ------- | ------------- | ------- |
| 串行(CPU 與 GPU 不重疊)   | 71.43 ms | 約 59.5 分    | 3,583   |
| CPU 預取完全隱藏(上限)    | 42.56 ms | 約 35.5 分    | 6,015   |

**尚未驗證:** 多進程預取能否逼近上限。單一 Python 執行緒在不含遮罩時只拿到 1.31 倍(56.2%),因為 GIL;含遮罩時 CPU 側是 GPU 步的 5.36 倍,執行緒應更不足。**H-B2 的實際耗時要用真正訓練迴圈量,不採用上表。**

**過程偏差:** 200 步冒煙測試以 27 通道與 14 通道各跑一次。書本候選集機率質量在 200 步(仍在 500 步 warmup 內,LR 僅到 4e-4)後為 27 通道 0.4018、14 通道 0.6358,兩者 argmax 都在候選集內(≥99.7%),且都是均勻下限的數千倍。**此比較不構成任何證據**:200 步時兩個網絡都還沒學到書本,差異屬初始化與早期動態的噪聲。決定 17 的理由是結構性的(`own_move_count` 成為顯式輸入),不是這個數字。
