## 2. 捆綁改動，不可拆因

本 run 相對學習者自己的 0k→20k 那一輪（`eval/rl-single-train/`）**同時改變多件事**：

1. **池**：七人格、無放回抽 3 → **十席自訂池**（七人格 + 三個凍結網路席），其中 **包含學習者自己的起點 `rl_h1000_20k`**（自我對戰例外，見 §3）。
2. **排程**：均勻抽樣 → **平衡排程** `--balanced-schedule`。
3. **種子段**：7,000,000–7,019,999 → **7,680,000–7,709,999**（全新段）。
4. **輪號**：1…40 → **1…60**（另一條 60 輪，不延續 20k 的輪號）。
5. **檔名**：輸出 step 由 1 起算 → **在起點 40 之上累加**，最終檔名 `step_000100.pt`。

> **這五項是一包，結果只能歸因到整包。** 任何「是因為 X 才變好／變差」的說話都不成立——
> 包含「平衡排程讓它變強」「自我對戰讓它變強」「移除自我對戰會更好」。
> 要拆，只能各自單開對照 run，那是新的決定，由使用者下。

本 run 與 `rl_o1000_50k_v3`（`eval/rl-single-train-v3o/`）**不是同一個實驗**：學習者不同（h vs o）、池組成不同（本池保留 `rl_h1000_20k`、以 `rl_o1000_50k_v3` 取代 v3o 池中的 `rl_i1000_50k`）、種子段不同、席位名不同。v3o 的 +0.2286 不能當本 run 的先驗或門檻。

本 run 與 `eval/rl-multiple-train/big_eval/` 第六輪（h 單打重走 v2h，`--resume` 自 `data/multi/h/step_000080.pt`、七人格、無平衡排程）也**不可比**：那個計畫從未開跑（`data/rl_h50k_v2/` 只有前置檔、沒有 `rounds.jsonl`），且起點是 multi 的 80 輪檔，**不是**本 run 的起點。

## 8. Adam 冷啟動風險與 guardrail 觀察重點

### 8-1 冷啟動是什麼（事實）

`--init` 路徑只載入**權重**（`rl.rl_train._start_net` → `rl.policy.load_policy`），blob 為空：**Adam 狀態不還原、`entropy_reference` 不沿用起點檔的 1.5294075409571335**（該值存在檔內，冷啟動路徑不讀）。優化器由 `_make_optimizer` 全新建立，動量一階／二階皆為零。起點檔內其實存有 Adam 狀態，但本 run **不用它**。

### 8-2 風險（機制推測，標明為推測）

動量為零時，Adam 最初數步的更新量接近 `lr × sign(g)`（有效步長偏大），常見行為是前幾輪 policy_loss / value_loss 出現一次性震盪後回落。**這是機制常識，不是對本 run 的預測。** 若前幾輪就觸發 guardrail，照 §8-3 處理，不調參。

### 8-3 guardrail（沿 plan10 §6，跑後不改）

| guardrail | 條件 | 本 run |
|---|---|---|
| `nan_or_inf` | 統計欄位非有限值 | 觸發即停 |
| `kl_anchor` | `kl > 0.05` | `kl_coef = 0` → **永不觸發** |
| `entropy` | `ent < 0.5 × entropy_reference` | reference = **本 run 第 1 輪**實測值（§8-1） |
| `first_ratio_dev` | `> 1e-6` | 觸發即停 |
| `disk` | free < 5.0 GB | 唯一可續跑的例外（開訓前實測 1.1T free） |

- **`entropy_reference` 來自新環境**：本 run 第 1 輪、10 席池、平衡排程下量到的 entropy（**不是**起點檔的 1.5294…）。閾值 = 0.5 × 該值。它同樣是「第 1 輪單點」，穩定性有限，記錄在此。
- **觀察重點**：
  1. **前 5 輪**：`policy_loss`、`value_loss`、`clip_fraction`、`explained_variance` 是否出現冷啟動震盪；`entropy` 對 reference 的比值。
  2. **全程**：`learner_reward_mean` / `learner_rank_mean` 趨勢（曲線，不入判準）、guardrail 值每輪記錄於 `rounds.jsonl`。
  3. 觸發任一非 `disk` 者：該輪已存檔、exit 1，訓練視為**未完成**——不評測、不入池、不續跑、不調閾值、不開第二條；結果照記為「第 k 輪被 `<name>` 中止」，附 entropy 軌跡，停下等裁示。
- 中途不得因 entropy 下滑手動介入；不設「達到 30,000 局前自動停止」以外的停止條件。

## 10. 凍結席 sha256 前後對照（plan10 §3 步驟 3、§8 風險 10）

三個網路席檔案（權限皆可寫，必須真的檢查，不能靠唯讀保證）：

| 席位 | 路徑 | sha256（**階段 0，開訓前**） |
|---|---|---|
| `rl_b1000_50k` | `ai/checkpoints/rl_b1000_50k/step_000100.pt` | `ab6ec0a120667bd98a8f0352c7e35b5c6ac1ec17126a433050fdb93be92d09e3` |
| `rl_o1000_50k_v3` | `ai/checkpoints/rl_o1000_50k_v3/step_000060.pt` | `0868776ef18ad2b3e2e00878fe0cf87fd2202ef47dcd9dde8e96f86e7db1154d` |
| **起點／池席 `rl_h1000_20k`** | `ai/checkpoints/rl_h1000_20k/step_000040.pt` | `e1dc6230a70d205a89287468c47db6126717f0e9d42369bc1beca31404801636` |

七個格席位是程式碼不是權重，沒有檔可雜湊；它們仍可解析由 `python -m ai --check` 把關（階段 0 與階段 1 各跑一次）。

**方案**：

```
階段 0（開訓前）  對三檔各算 sha256，比對上表逐字相同；不同則停
                  另跑 python -m ai --check
                  佈置 data/rl_h50k_v3/，驗起點檔 sha256 = e1dc6230…
階段 1（開訓後）  再算一次，三個 sha256 與階段 0 逐位相等
                  任一不同 → 凍結席被寫 → 訓練作廢，停下等裁示
```
