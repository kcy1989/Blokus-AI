## 2. 捆綁改動，不可拆因

本 run 相對學習者自己的 0k→20k 那一輪（`eval/rl-single-train/`）**同時改變多件事**：

1. **池**：七人格、無放回抽 3 → **十席自訂池**（七人格 + 三個凍結網路席），**不含**學習者自己的起點（plan10 預設形狀，非例外）。
2. **排程**：均勻抽樣 → **平衡排程** `--balanced-schedule`。
3. **種子段**：7,200,000–7,219,999 → **7,730,000–7,759,999**（全新段）。
4. **輪號**：1…40 → **1…60**（另一條 60 輪，不延續 20k 的輪號）。
5. **檔名**：輸出 step 由 1 起算 → **在起點 40 之上累加**，最終檔名 `step_000100.pt`。

> **這五項是一包，結果只能歸因到整包。** 任何「是因為 X 才變好／變差」的說話都不成立——
> 包含「平衡排程讓它變強」。要拆，只能各自單開對照 run，那是新的決定，由使用者下。

### 與舊 `rl_i1000_50k_v2` 的關係（不同實驗，不可比）

- 同名數字 `v2` 已由**早先的 i 單打續訓**使用（`resume` 自 round 41、**11 席池**、種子段 7,170,000–7,199,999 與 7,540,000–7,540,999，證據 `eval/rl-single-train-v2i/`），結果 argmax **−0.029730（比值 −0.719）→ 未通過、未入池**。本 run 因此改叫 **v3**，一個名字不對兩份權重。
- 兩者差在：本 run 是平衡排程＋冷啟動＋十席池（舊的是有放回抽樣＋續訓＋11 席池）；本 run 的池**不含** `rl_i1000_50k`（舊的池含它——那違反 plan10 §1 檢查 3）；種子段、輪號、檔名全不同。**結果不可互相比較或合併。**

### 6-1 平衡排程管到的維度：實測全平（60 輪，本池）

以本 run 的實際參數（pool 如 §3、`round_no` 1…60、`rng_seed=7730000`）逐輪生成 specs 實測：

| 維度 | 每輪 | 60 輪累計 |

| 學習者座位 | 精確各 **125** | 精確各 **7,500** |
| 池席出場 | 精確各 **150**（spread 0） | **每席 9,000，spread 0** |
| 格子矩陣（座位×池席） | 行和 375、列內 spread ≤ 1、格值 **{37, 38}** | 列內 spread 0 |
| 局內對手 | 三名互異 | — |
| 局序 | 由 `(seed, round)` 決定、可重放、連續兩輪不同 | — |

（10 席下每輪 1,500 個對手槽位 ÷ 10 席 = 150，**沒有餘數**，所以每輪與累計都是精確平。）

### 6-2 兩兩共現：**只報數，不平衡（殘留）**

| 指標 | 實測 |
|---|---|
| 出現的對數 | **45 / 45**（無零對） |
| 累計次數 | min **1,423**、max **2,830**（均值 2,000）、**spread 1,407** |

**為什麼不修**：每輪 3×500 = 1,500 個對槽位 ÷ C(10,2) = 45 → **餘 15**，單輪完全均等算術上不可達；逐學習者座位 3×125 = 375 ÷ 45 亦餘 30。2026-10-13 裁示明文：**兩兩共現只報數**，平衡排程對它不設限。

最疏兩對（實測）：`optimizer×builder` 1,423、`hunter×wolf` 1,486。

### 6-3 方法與一項必須記下的不一致

上表由「`rng_seed = seed_base`、逐輪重新播種」這條路徑生成——也就是 `rl_train` 實際傳給 `make_specs` 的形狀（`rl/rl_train.py` 的 `make_specs(..., rng_seed=cfg.seed_base, ..., round_no=round_no)`）。

**一項不一致（紀實，沿用 h run 的記錄）**：用同一套碼重算 `eval/rl-single-train-v3o/README.md` §6-2 自己的數字（10 席、base 7,620,000），得 min 1,276／max 2,640／spread 1,364、逐輪 48–93 均 70.4，與該檔記的 1,355／2,778／1,423、63–101 均 84.5 **對不上**；另試三種 rng 慣例也無一重現。結論：那份調查的方法無法由現行碼路徑重現。**本檔的數字以可在碼裡對上的路徑為準，方法如上；不宣稱與 v3o 的兩兩共現數字同源。**

## 7. 管線非逐位重現（不作逐位宣稱）

**本專案的訓練管線跨進程不是逐位確定的，本檔案不作任何「逐位重現」宣稱。**

- 2026-10-13 實測（`7310cf7` 的提交訊息與 `tests/test_rl_train.py` 模組 docstring 記載）：60 次重跑中 3 次 `torch.equal` 失敗，差異張量為 trunk 權重，**max|Δ| ≈ 2.6e-5**、mean|Δ| ≈ 1e-7~5e-7；**對局本身逐位相同**（`rounds.jsonl` 的 reward/rank 兩側完全相等），分歧從第 1 輪的 float 路徑起步，兩步 Adam 放大。與 xdist 無關、與執行緒數 >1 無關（全釘 1 仍發生）。

- 報告若比較本 run 與任何重跑，差異 ≤ 1e-5 量級應先視為管線噪音，不是訓練差異。

## 8. Adam 冷啟動風險與 guardrail 觀察重點

### 8-1 冷啟動是什麼（事實）

`--init` 路徑只載入**權重**（`rl.rl_train._start_net` → `rl.policy.load_policy`），blob 為空：**Adam 狀態不還原、`entropy_reference` 不沿用起點檔的 1.394941998852624**（該值存在檔內，冷啟動路徑不讀）。優化器由 `_make_optimizer` 全新建立，動量一階／二階皆為零。起點檔內其實存有 Adam 狀態，但本 run **不用它**。

（已知事實：i 的 20k 之 `entropy_reference` 是四個 20k 裡最低的（1.3949），見 `eval/rl-single-train-v2i/README.md`；但本 run 的 reference 由第 1 輪新環境實測設定，兩者無關。）

### 8-2 風險（機制推測，標明為推測）

動量為零時，Adam 最初數步的更新量接近 `lr × sign(g)`（有效步長偏大），常見行為是前幾輪 policy_loss / value_loss 出現一次性震盪後回落。**這是機制常識，不是對本 run 的預測。** 若前幾輪就觸發 guardrail，照 §8-3 處理，不調參。

### 8-3 guardrail（沿 plan10 §6，跑後不改）

| guardrail | 條件 | 本 run |
|---|---|---|
| `nan_or_inf` | 統計欄位非有限值 | 觸發即停 |
| `kl_anchor` | `kl > 0.05` | `kl_coef = 0` → **永不觸發** |
| `entropy` | `ent < 0.5 × entropy_reference` | reference = **本 run 第 1 輪**實測值（§8-1） |
| `first_ratio_dev` | `> 1e-6` | 觸發即停 |
| `disk` | free < 5.0 GB | 唯一可續跑的例外（開訓前實測 1.1T free） |

- **`entropy_reference` 來自新環境**：本 run 第 1 輪、10 席池、平衡排程下量到的 entropy。閾值 = 0.5 × 該值。它同樣是「第 1 輪單點」，穩定性有限，記錄在此。
- **觀察重點**：
  1. **前 5 輪**：`policy_loss`、`value_loss`、`clip_fraction`、`explained_variance` 是否出現冷啟動震盪；`entropy` 對 reference 的比值。
  2. **全程**：`learner_reward_mean` / `learner_rank_mean` 趨勢（曲線，不入判準）、guardrail 值每輪記錄於 `rounds.jsonl`。
  3. 觸發任一非 `disk` 者：該輪已存檔、exit 1，訓練視為**未完成**——不評測、不入池、不續跑、不調閾值、不開第二條；結果照記為「第 k 輪被 `<name>` 中止」，附 entropy 軌跡，停下等裁示。
- 中途不得因 entropy 下滑手動介入；不設「達到 30,000 局前自動停止」以外的停止條件。

七個格席位是程式碼不是權重，沒有檔可雜湊；它們仍可解析由 `python -m ai --check` 把關（階段 0 與階段 1 各跑一次）。

**方案**：

```
階段 0（開訓前）  對四檔各算 sha256，比對上表逐字相同；不同則停
                  另跑 python -m ai --check
                  佈置 data/rl_i50k_v3/，驗起點檔 sha256 = 3db862d3…
階段 1（開訓後）  再算一次，四個 sha256 與階段 0 逐位相等
                  任一不同 → 凍結席被寫 → 訓練作廢，停下等裁示
                  另跑 python -m ai --check
```

唯讀依據：`rl/rl_train.py` 的唯一寫入來自 `save_checkpoint`，路徑一律在 `data/rl_i50k_v3/`；`rl/rollout.py` 對池席只有 `load_policy` / `torch.load`。

## 11. 輸出、命令與時間估計

### 命令（開訓用；無 `--resume`，`--rounds` 已移除）

```bash
python -m rl.rl_train \
  --init ai/checkpoints/rl_i1000_20k/step_000040.pt \
  --anchor ai/checkpoints/rl_i1000_20k/step_000040.pt \
  --out data/rl_i50k_v3 \
  --games 30000 --per-round 500 \
  --seed-base 7730000 \
  --balanced-schedule \
  --n-procs 8 \
  --eval-every 5 \
```

### 14-5 迴圈內曲線與判據的關係（必須記下的一個形狀）

迴圈內曲線**中位 +0.19、12 點中 11 正、峰值 +0.334（round 35）**，而判據跑出 **−0.036**。這個落差**不是矛盾**，兩個原因：

2. **因此誠實的記法**：本 run 的迴圈內曲線**高估了**最終模型的實力。曲線量的是「每一輪的當前權重」在 100 個固定局面上的表現，判據量的是「最終權重」在 1000 個新局面上與起點的差。兩者可以不一致，而這次不一致的方向是曲線偏樂觀。任何引用 +0.334 的報告都必須同時引用 −0.036。
