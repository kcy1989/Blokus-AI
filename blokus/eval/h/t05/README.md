## 2. 這條 run 在譜系裡的位置（先講清楚，免得以後誤讀）

本 run 是溫度 T 的單變量診斷：與 h100k 運作完全相同（同起點、同 12 席池、同平衡排程、同種子段寬度），唯一變項是 rollout 溫度從 T=1.0 改為 **T=0.5**。

h 線目前有六個名字指六組權重：

| 席位 | 是什麼 | 狀態 |
|---|---|---|
| `rl_h1000_20k` | 0k→20k | 已入池、已驗證 |
| `rl_h1000_50k` | multi 的 100 輪版 | 已入池 |
| `rl_h1000_30k` | v3 run 的 round 20 | 已入池（+0.052220／1.477 se vs 20k） |
| `rl_h1000_50k_v2` | v3 run 的 round 60 | 未過判據、未入池 |
| `rl_h1000_50k_v4` | 從 30k 出發的 40 輪 | 未過判據、未入池（−0.017660） |
| `rl_h1000_100k` | h100k run 的 105 輪（T=1.0） | 未過判據、未入池（+0.008050） |
| **本 run（T=0.5）** | 從 v4 r35 出發的 60 輪 | 本檔的對象，**不入判準池** |

→ 本 run 的起點與 h100k 相同（v4 run 的 round 35），這是一條從未入池的中段權重。

### 捆綁改動，不可拆因

本 run 相對「T=1.0 的 h100k」只改變一件事：

1. **溫度**：T=1.0 → **T=0.5**（rollout、rescore、PPO 更新、KL、熵全部採 logits/T）

> **這一項是單變量，結果可歸因到溫度。** 若 h100k 已經「未過線」，本 run 是在問「降溫到 0.5 是否讓 argmax 表現變好」。兩者差異只能歸因到 T。

## 4. 評測判準（預先寫死，一次定案）

### 評測規格

- **評測對象**：訓練後的最終模型（`step_000155.pt`）vs 起點對照（`step_000035.pt` / v4 r35）。
- **評測種子**：7,919,000–7,919,999（`RL_T05_EVAL_BLOCK`，FREE 段，不與任何已評測區重疊）。
- **對手池**：預設七人格（wolf, chess, fox, hunter, optimizer, builder, intruder），同 specs 配對，兩側同 specs。
- **模式**：argmax（主判準）與 softmax（T=0.5，只記錄，不入判準）。
- `paired_diff = mean(reward_current − reward_start)`。

### 通過條件（主判準：argmax 單模式）

```
paired_diff > 0  且  paired_diff ≥ 1.3 × paired_se
```

- **停止規則（2026-10-16 裁示增補）**：若 `|paired_diff| < 0.1`，一律記為「無法區分」，**不得宣稱成功**；若判準為「無法區分」或為負，PPO 單打線**停止**，不再試其他 T。
- **單側假陽性率**：約 **9.7%**（$P(Z > 1.3)$）。1000 局下 `paired_se` 實測約 $0.037 \sim 0.044$，對應過線門檻約 $+0.048 \sim +0.057$。
- **softmax 模式（1000 局，同 specs）**：只記錄，不入判準，不得作為入池或拒絕理由。
- **直接決策**：跑完這 1000 局配對評測後即可直接判斷是否入池，**不需要再跑第二次複驗或其他額外評測**。
- **候選數固定為一條**，只比起點對照。

### 結論措辭

- 通過屬「弱證據」，報告不得寫「已證明更強」，且須聲明「歸因不可拆（單變量溫度）」、「評測池為七人格（未覆蓋訓練池內之網路席）」。
- 未通過：**不入池、不開第二條**，結果照記。

## 6. 溫度 T=0.5 的特定說明

- **rollout**：`_sample_from_masked` 採 `softmax(logits.detach().double() / 0.5, dim=-1)`，分佈更銳利，採樣更偏向 argmax 動作。
- **log_prob 記錄**：`rl/rollout.py` `play_game` 的 `record` 以 `logits / temperature` 呼叫 `log_prob_entropy`，與採樣分佈一致，否則 PPO ratio 不會是 1。
- **PPO rescore**：`rl/ppo.py` `_rescore` 與更新迴路均以 `logits / cfg.temperature` 重新計算 log_prob 與 entropy。
- **KL**：`kl_to_anchor(logits / T, a_logits / T)`，兩邊同除以 T。
- **熵統計與護欄**：全部以 `logits / T` 分佈計算；`entropy_reference` 取本 run 第 1 輪實測值。
- **guardrail `first_ratio_dev > 1e-6`**：T=0.5 下必須仍滿足（新增測試 `test_rl_rollout.py`、`test_rl_ppo.py` 釘住）。
- **預估牆鐘**：60 輪 × 約 93 s/輪 ≈ 45–50 分鐘（n_procs=8, CPU rollout）。

---

## 7. 停止與 guardrail 規則（預先寫死）

- guardrail：`nan_or_inf`、`entropy`（`< 0.5 × entropy_reference`）、`first_ratio_dev`（`> 1e-6`）、`disk`（`< 5.0 GB`）。觸發 → 存檔後中止，exit 1。（`kl_coef = 0` 時 `kl_anchor` 為 `None` 永不觸發）。
- 任何非 `disk` 的觸發：訓練視為未完成，**不評測、不入池、不續跑、不調閾值、不開第二條**。結果照記為「第 k 輪被 `<name>` 中止」，附 entropy 軌跡。停下等裁示。
- `disk` 例外：清出空間後 `resume=True` 續跑，證據註明。
- 不設「達到目標局數前自動停止」以外的停止條件。中途 entropy 下滑也不得手動介入。

---

## 8. 已知風險（須在證據 README 標明）

1. **argmax 不受訓練目標直接控制**：訓練 rollout 為 softmax($T=0.5$)，主判準為實際遊戲使用的 argmax。T<1 讓採樣更銳利，但 argmax 是否進步是獨立問題（h100k 證實 softmax 可上升而 argmax 不進步）。
2. **評測池差異**：訓練池含凍結網路席，而 §5 評測池為預設七人格（不含網路席），評測結論僅覆蓋七人格分布。
3. **管線跨進程浮點非逐位確定**：對局本身逐位可重現，但張量更新跨進程有 $\sim 10^{-5}$ 浮點尾差，不宣稱權重逐位重現。
4. **種子守衛**：7,889,000–7,918,999 與 7,919,000–7,919,999 與既有全部已註冊列 FREE 且互不重疊（`tests/test_rl_paired3.py` 釘住）。
5. **凍結席與學習者不得共用權重物件**：開訓前後以 sha256 逐位對照檢查。
