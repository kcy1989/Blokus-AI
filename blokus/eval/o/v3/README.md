## 2. 五項同時改變，不可拆因

本 run 相對上一次 o 的 50k 嘗試（v2o，證據在 `eval/o/v2/`）
**一次改變五件事**：

1. **池**：11 席 → **10 席**，移除學習者自我 `rl_o1000_20k`（不再自我對戰）。
2. **排程**：均勻抽籤 → **平衡排程** `--balanced-schedule`。
3. **起跑**：resume 續輪號 + 延續 Adam 慣量 → **冷啟動**（優化器歸零）。
4. **種子段**：7,550,000–7,579,999 → **7,620,000–7,649,999**（全新段）。
5. **輪號**：41…100 → **1…60**。

> **這五項是一包，結果只能歸因到整包。** 任何「是因為 X 才變好/變差」的
> 說話都不成立——包括把它歸給平衡排程或歸給移除自我。要拆，只能各自單開
> 對照 run，那是新的決定，由使用者下。

## 8. Adam 冷啟動風險與 guardrail 觀察重點

### 8-1 冷啟動是什麼（事實）

`--init` 路徑只載入**權重**（`rl.rl_train._start_net` →
`rl.policy.load_policy`），blob 為空：**Adam 狀態不還原、
`entropy_reference` 不沿用起點檔的 1.3728…**。優化器由
`_make_optimizer` 全新建立，動量一階/二階皆為零。起點檔內其實存有
43 參數的 Adam 狀態（v2o §8 實測），但案 B **不用它**——這是與 v2o 最大的
訓練差別（v2o 續訓時延續了學生跑的慣量）。

### 8-2 風險（機制推測，標明為推測）

動量為零時，Adam 最初數步的更新量接近 `lr × sign(g)`（有效步長偏大），
常見行為是前幾輪 policy_loss / value_loss 出現一次性震盪後回落。**這是
機制常識，不是對本 run 的預測。** 若前幾輪就觸發 guardrail，照 §8-3 處理，
不調參。

### 8-3 guardrail（沿 plan10 §6，跑後不改）

| guardrail | 條件 | 本 run |
|---|---|---|
| `nan_or_inf` | 統計欄位非有限值 | 觸發即停 |
| `kl_anchor` | `kl > 0.05` | `kl_coef = 0` → **永不觸發** |
| `entropy` | `ent < 0.5 × entropy_reference` | reference = **本 run 第 1 輪**實測值（見下） |
| `first_ratio_dev` | `> 1e-6` | 觸發即停 |
| `disk` | free < 5.0 GB | 唯一可續跑的例外 |

- **`entropy_reference` 來自新環境**：本 run 第 1 輪、10 席池、平衡排程下
  量到的 entropy（**不是**起點檔的 1.3728…，那個值本 run 根本不讀）。
  閾值 = 0.5 × 該值。它同樣是「第 1 輪單點」，穩定性有限——這是
  plan10 §8 風險 8 的變形，記錄在此。
- **觀察重點（裁示 6）**：
  1. **前 5 輪**：`policy_loss`、`value_loss`、`clip_fraction`、
     `explained_variance` 是否出現冷啟動震盪；`entropy` 對 reference 的比值。
  2. **全程**：`learner_reward_mean` / `learner_rank_mean` 趨勢（曲線，
     不入判準）、guardrail 值每輪記錄於 `rounds.jsonl`。
  3. 觸發任一非 `disk` 者：該輪已存檔、exit 1，訓練視為**未完成** ——
     不評測、不入池、不續跑、不調閾值、不開第二條；結果照記為
     「第 k 輪被 `<name>` 中止」，附 entropy 軌跡，停下等裁示。
- 中途不得因 entropy 下滑手動介入；不設「達到 30,000 局前自動停止」以外
  的停止條件。

## 11. 輸出、命令與時間估計

### 命令（開訓用；無 `--resume`，`--rounds` 已移除）

```bash
python -m rl.rl_train \
  --init ai/checkpoints/rl_o1000_20k/step_000040.pt \
  --anchor ai/checkpoints/rl_o1000_20k/step_000040.pt \
  --out data/rl/o/50k_v3 \
  --games 30000 --per-round 500 \
  --seed-base 7620000 \
  --balanced-schedule \
  --n-procs 8 \
  --eval-every 5 \
  --opponent-pool "rl_b1000_50k,hunter,rl_i1000_50k,wolf,chess,fox,rl_h1000_20k,optimizer,builder,intruder"
```

先跑 `--dry-run` 對一次計畫（估時常數已是 2026-10-13 實測值：
**62 s rollout + 31 s update / 500 局**）。

### 估計

| 項 | 計算 | 時間 |
|---|---|---|
| 訓練 | 60 × 93 s | **≈ 93 分** |
| 迴圈內評測 | 12 次 × 100 局 × 2 模型，`n_procs=4` | ≈ 8 分（v2o 同型實測） |
